# SPBU Research Network

Обновленный интерактивный дашборд по публикациям авторов СПбГУ, построенный на данных [OpenAlex API](https://docs.openalex.org/).

Дашборд показывает **сеть соавторства** (граф «кто с кем публикуется»), профили авторов,  сравнение авторов, темы научных направлений и общую аналитику публикаций.

## Возможности

| Страница | Путь | Что делает |
|---|---|---|
| **Обзор** | `/` | Карточки с ключевыми метриками, мини-граф сети (топ-60 авторов), топ направлений, динамика публикаций по годам. |
| **Исследователи** | `/researchers` | Поиск и фильтрация авторов, сортировка, пагинация, карточки с метриками. |
| **Сеть соавторства** | `/network` | Интерактивный граф (Cytoscape): узлы — авторы, рёбра — совместные публикации. Фильтры по публикациям, цитированиям и научным направлениям. Поиск автора с выделением на графе. |
| **Профиль автора** | `/author/<author_id>` | Метрики автора, все публикации (со ссылками на OpenAlex), топ соавторов, темы. |
| **Темы** | `/topics` | Список научных направлений, поиск темы, динамика по годам, все авторы темы, переход на граф с фильтром. |
| **Аналитика** | `/analytics` | Фильтры по периоду и направлению, динамика публикаций, топ направлений, топ исследователей, растущие и падающие направления. |
| **Сравнение** | `/compare` | Прямое сравнение двух авторов: метрики рядом, общие/уникальные темы, динамика публикаций. |
| **Поиск в navbar** | — | Автокомплит по авторам с переходом в профиль (со всех страниц). |

## Стек

- **Python 3.14**, **Dash** (multi-page), **Dash Bootstrap Components**, **Dash Cytoscape**
- **Plotly**, **NetworkX**, **pandas**, **numpy**
- **SQLite** (сырой `sqlite3` + `pandas.read_sql`)
- **OpenAlex REST API** (загрузка данных), **Docker / Docker Compose**

## Запуск

### 1. Локально через venv

```bash
# один раз: создать окружение и поставить зависимости
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# запуск: если данных нет, ETL запустится сам (нужен интернет)
./start.sh
```

Достаточно просто запустить код — если `pure_data.db` отсутствует или пуст,
приложение автоматически загрузит данные из OpenAlex перед стартом. Работает и
напрямую: `cd app && python app.py`.

Дополнительные флаги:

```bash
./start.sh --force-etl   # принудительно обновить данные, затем запуск
./start.sh --etl-only    # только обновить данные, без запуска дашборда
./start.sh --no-etl      # запуск без авто-загрузки данных
```

Дашборд будет доступен по адресу **http://localhost:8050**.

### 2. Через Docker

```bash
docker compose up --build -d
# http://localhost:8050
```

Папка `app/` подключается в контейнер как bind-mount (`./app:/app/app`), поэтому:

- код меняется на лету (для применения правок Python нужен `docker compose restart app`);
- база `pure_data.db` живёт на хосте и не пропадает при пересборке образа;
- при первом старте с пустой базой ETL запустится автоматически (нужен интернет из контейнера);
- `DASH_DEBUG=0` — один процесс, `docker compose stop` мгновенно освобождает порт 8050.

## ETL и данные

`etl.py` загружает из OpenAlex:

- авторов из списка `MAIN_AUTHORS` (задаётся в `app/utils.py`);
- их публикации и соавторов.

Данные складываются в SQLite (`app/pure_data.db`), таблицы:

- `publications` — публикации (заголовок, год, цитирования);
- `authors` — авторы (id, имя);
- `authorship` — связи «публикация ↔ автор»;
- `etl_metadata` — служебная информация (время последнего прогона).

Повторный запуск ETL использует `content_hash`: обновляются только изменившиеся записи, поэтому прогон дешёвый.

## Кэш графа и раскладка

Главная страница строит граф соавторства один раз и сохраняет его в `app/graph_cache.pkl`. Ключ кэша — **mtime файла `pure_data.db`** + `CACHE_VERSION` (константа в `app/pages/network.py`):

- ключ считается заново при каждом запросе — одна дешёвая операция `stat`, без запросов к БД;
- после прогона ETL mtime базы меняется, ключ становится другим, и при следующем открытии/перезагрузке страницы граф пересобирается **автоматически, без рестарта приложения**;
- после изменения кода построителя графа поднимите `CACHE_VERSION`, чтобы инвалидировать старый кэш.

Раскладка **детерминированная** (`seed=42`):

- каждый компонент связности раскладывается отдельно;
- компоненты упаковываются в ряды с зазорами, чтобы кластеры не пересекались;
- позиции считаются на сервере один раз и применяются клиентом через `preset`-layout — без пересчёта `cose` при каждом открытии страницы.

## Конфигурация

| Параметр | Где | По умолчанию | Описание |
|---|---|---|---|
| `MAIN_AUTHORS` | `app/utils.py` | список авторов СПбГУ | Анализируемые авторы |
| `DASH_DEBUG` | env | `0` | Режим отладки Dash (`1` включает live-reload) |
| `AUTO_ETL` | env | `1` | Авто-загрузка данных при запуске, если базы нет (`0` — выключить) |
| Порт | `app/app.py` | `8050` | HTTP-порт дашборда |

## Решение проблем

### Граф на главной пустой (0 узлов)

Это ожидаемо для свежего клона: данные **не хранятся в git**. Файлы `pure_data.db` и `graph_cache.pkl` находятся в `.gitignore` — они генерируются ETL при первом запуске.

На свежем клоне отдельная загрузка не нужна: при первом запуске приложение **само запустит ETL**, если базы нет или она пустая (нужен интернет). Просто запустите `./start.sh` (или `cd app && python app.py`) и дождитесь загрузки.

Если нужно запустить загрузку вручную (обновить данные, отладить ETL):

```bash
# локально: только загрузка данных
.venv/bin/python etl.py --once
./start.sh --etl-only
```

В Docker:

```bash
# одноразовый контейнер с ETL (пишет в bind-mount на хост)
docker compose run --rm app python etl.py --once

# или внутри уже запущенного контейнера
docker exec spbu-dashboard python etl.py --once
```

После этого в `app/` появится `pure_data.db`, и граф наполнится.

Проверка, что данные загрузились:

```bash
ls -la app/pure_data.db
```

Если файл есть, но граф всё равно пустой:

- запустите ETL ещё раз и посмотрите лог `app/app.log`: там будет либо строка «Загружено N публикаций» (данные в порядке), либо ошибки OpenAlex (например, нет сети или лимиты запросов API);
- если сравнение авторов работает (данные в БД есть), а граф пустой — просто перезагрузите страницу: приложение следит за mtime `pure_data.db` и само перестроит граф после ETL. (В версиях до этого фикса требовался перезапуск приложения.)

### Ошибки с dcc.Location / DuplicateIdError
Dash при use_pages=True не любит dcc.Location в app.layout — может быть дубликат с внутренним location Dash. Поэтому решено не использовать _pages_location в layout, а dcc.Location держать внутри каждой страницы (home-url, network-url, author-url и т.д.).

### Подсветка активной ссылки в navbar
Подсветка работает через **`app/assets/custom.js`** — JS отслеживает смену URL и добавляет класс `active` нужной ссылке в navbar.  
`dcc.Link` используется для SPA-навигации между страницами (без перезагрузки), но **гарантированная подсветка** обеспечивается именно JS-скриптом.
